How to read this report

  • proved Lean checked a theorem stating the property for the exact submitted values.
  • refuted Lean (or, for native correctness, the generated code) produced a concrete counterexample for the exact submitted values.
  • not established This method did not establish the property. It is not a counterexample; a timeout or a missing tool lands here.
  • unsupported The input is outside the supported model.

Design guarantees and implementation correspondence are separate chains: a circuit can compute its matrix exactly while the matrix diffuses poorly, and an MDS matrix can have a miswired circuit. A Lean proof is accepted only when its printed statement equals the expected statement about the exact inputs and its axioms are within propext, Classical.choice, Quot.sound.

How to verify

From a Cryptificate checkout prepared with scripts/setup.sh:

npx cryptificate verify aes-wrong-wire.tar.gz

verify reads only inputs.json and report.json from the bundle. It regenerates the Lean certificate with the installed engine and templates, runs the installed Lean checker, recomputes each claim and compares it with the status recorded here. It never runs Lean, Rust or shell code from the bundle, and it ignores this page (report.html), which is a rendering of report.json, not evidence.

For an analysis it re-checks the design claims and circuit.equivalence, and native.correctness with --native (from regenerated Rust, never the bundled Rust). It does not re-check rust.refinement or timings; they are shown with their recorded status.

To render this page again from a bundle or a report.json without running anything:

npx cryptificate report aes-wrong-wire.tar.gz --format html --output report.html
